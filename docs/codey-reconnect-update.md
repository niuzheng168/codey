# Codey：允许短暂断连的更新

日期：2026-09-19。基于 `bf65713` 的后续开发；**不是零中断更新，也不是新的公开发行包**。
gh 认证复用已独立提交，本功能不改变账号选择、登录或令牌保存方式。

## 用户操作

当前实现面向 **Linux x64 的已安装 systemd 用户节点**：

```sh
codey update "/absolute/path/codey.tgz" --sha256 TRUSTED_SHA256 --check --json
codey update "/absolute/path/codey.tgz" --sha256 TRUSTED_SHA256 --background --json
codey update --status --json
codey doctor
```

`TRUSTED_SHA256` 替换为独立核验的 64 位十六进制摘要。
在 Codex/Workspace 进程树中执行普通 `codey update FILE.tgz`，自动选择同一后台流程。
外部终端不加 `--background` 时仍同步执行。完整参数以
[CLI 参考](../skills/config-new-codey-machine/references/codey-cli.md) 为准。

- 不需要关闭客户端，也不停止不属于本节点的服务或独立 Codex app-server。
- **提交成功不等于更新完成**。核对 `jobId`，等待 `completed`，再做 `doctor` 验收。
- Workspace 已有断线重试及会话/侧栏重新同步；不会自动重放聊天指令、工具调用或终端命令。
- 正在进行的模型输出、服务内 PTY、插件和浏览器任务可能中断。先保存工作；长任务宜等结束再更新。
- 会话文件、身份、TLS 和凭据保留；不迁移所有内存状态。页面中的旧 JavaScript 不会原地替换，
  需要加载新版前端资源时刷新页面即可，不必退出整个客户端。
- Windows/macOS 暂不开放后台模式，不把 Linux 验收称作跨平台实测。
- 后台模式要求当前 CLI 和目标包都支持该任务协议；切回不含此功能的旧包时，
  使用原用户外部终端同步更新，而不是强行绕过后台兼容性检查。
- 旧 CLI 不会因为目标包包含新功能就自动获得它。首次升级仍由原用户的外部上下文，
  或明确授权的一次性原生任务调用**原安装的更新命令**；不篡改已安装脚本或删掉安全检查。

## 执行与失败边界

1. 校验本地包、平台、Node、依赖锁及服务归属，取得现有 `install.lock`。
2. 将包复制进用户私有任务目录并复核 SHA-256；任务记录不含凭据。
3. 创建独立 systemd 用户瞬态服务。它是一次性、无重试、非开机启动的任务，不是新增常驻代理。
   子进程使用清理后的环境，不把调用终端的密钥、`NODE_OPTIONS` 或 npm 配置传入后台任务。
4. 任务验证自身确为该瞬态服务的主进程，并以原子方式**一次性接管原锁**。
   不通过删除旧锁、新建另一把锁或简单 `nohup` 来交接。
5. 旧服务继续运行，新包在独立目录准备和验证；相同依赖锁可离线复制并验证依赖。
6. 保存私有配置备份，留出 5 秒，再复核配置、工具、端口和非一次性服务的启停状态。
   外部修改、检查失败或切换前进度写入失败时，直接停止更新，**不进入停服回退**。
7. 只切换需要重启的服务。Linux 原生 DevTunnel 定义未变化时保留 host；
   gh host 的包装程序路径变化时，连同其续期/健康守护切换。
8. 检查恢复的服务及本地 TLS/SSO/网关，再写完成报告。切换后的错误才触发回退，
   旧服务也要通过健康检查；回退不完整保留操作锁并要求人工检查。

`--status` 读取私有报告并检查原生任务，再重读报告，避免任务恰好完成并被回收时误报。
总线查询失败且任务仍无终态时显示 `needs-review`，退出码非零；不输出任意子进程报错内容。
损坏或过期的请求记录由独立任务写入私有诊断，不执行新包、不接管别人的锁。

私有报告位于 `~/.config/codey-machine/updates/<jobId>/`，最近任务索引是
`last-update.json`。报告/错误日志不应上传聊天或公开存储。中断后不要强删锁、盲目重试，
也不要用重跑安装来恢复。CLI 不自动清理旧版本。

这里只回退程序指针、托管配置和服务状态，**不回滚数据库或会话内容**。
不兼容的数据迁移需要单独评审，不能把任意旧包视为安全的数据库降级方案。

## Windows 原生参数回归

`0.1.18` 和 `0.2.0` 的 Windows 执行桥错误地拒绝参数中的 CR/LF。更新准备阶段的
`node -e` 解包脚本是多行文本，因此实际更新可能报
`Windows native run failed (RuntimeException, line 117)`，而只读 `--check` 仍会通过：
后者验证包、版本和服务归属，不执行解包或原生模块验证。

修复保留直接进程启动（不经过 shell）和 CRT 引号/反斜杠转义，允许引号内的 CR/LF，
仍拒绝不能传入原生命令行的 NUL。`test/windows-native-client.test.mjs` 覆盖真实
PowerShell 5.1 执行、参数逐字往返，以及真实 `prepareUpdate` 的离线解包、依赖复用和
运行包检查；不是仅用替代执行器测试更新流程。

这个错误发生在停服/切换之前；正常异常清理会移除本次暂存目录并释放锁。
仍应核对 `codey status`，不能从报错文字推断所有失败都已安全回退。
新包内的修复不会替换正在执行的旧升级器；不要直接改动已安装文件或其校验摘要，
也不要通过删锁、重跑安装或清除节点身份来绕过问题。

## 验证

隔离测试覆盖自动后台选择、重复提交/锁竞争、主进程身份、配置漂移、端口/工具变化、
准备失败、进度写入失败、回退失败、完成报告与原生任务回收的竞态，以及故障状态退出码。
客户端测试覆盖重试、重新同步通知和不重复发送有副作用的消息。

原生测试入口为 `test/codey-reconnect-native.mjs`，必须显式指定 `--apply`、目标机名、
包路径、摘要及新私有报告目录。测试从**模拟 Codex 祖先**提交实际 CLI 更新，
随后只停止自身专用提交服务，验证更新任务独立存活、真实鉴权 WebSocket 重连、
凭据/配置摘要不变和其他服务 PID/状态不变。

首轮原生验证（2026-09-19，开发构建 A → B）：

| --- | ---: | ---: |

| 停服、切换与本地验收 | 4.950 秒 | 2.297 秒 |

以上 WebSocket 时间测的是**本机直连 Workspace**；不是通过外网隧道/Portal 浏览器的延迟保证。
